# 内容蒸馏方法（与 cangjie-skill 联动）

本文档说明 douyin-distiller 的阶段 8（内容蒸馏）如何与 cangjie-skill 联动，把抖音逐字稿蒸馏成可执行的 Skill 组。

---

## 蒸馏 vs 摘要：本质区别

| 维度 | 摘要 | 蒸馏（本 Skill 做的事） |
|------|------|------------------------|
| 目标 | 让人快速了解内容讲了什么 | 把方法论拆成可被 AI 在真实场景下调用的 Skill |
| 产出 | 一段概括文字 | 一组结构化的 Skill（含触发条件、可执行步骤、边界） |
| 关键字段 | 主旨、要点 | trigger（何时调用）、E（可执行步骤）、B（边界） |
| 失败模式 | 概括不准 | trigger 不准→永不调用或乱调用 |
| 成功标准 | 读者"有收获" | 真实问题被解决 |

**核心洞察**：现有读书方法论都是为人类读者蒸馏，不是为 agent 执行者蒸馏。蒸馏的所有扩展（三重验证、E/B 段、测试用例）都是为了解决这个目标迁移带来的新问题。

---

## RIA-TV++ 流水线总览

```
阶段0: 整稿理解 (Adler四步)      → BOOK_OVERVIEW.md
阶段1: 5个提取器并行提取          → candidates/ (框架/原则/案例/反例/术语)
阶段1.5: 三重验证筛选             → verified.md + rejected/
阶段2: RIA++ 构造 Skill           → 每个方法论一个 SKILL.md
阶段3: Zettelkasten 链接          → INDEX.md + GLOSSARY.md
阶段4: 压力测试 (darwin兼容)      → test-prompts.json + 回炉淘汰
阶段5: 交付                        → DIGEST.md + 安装到 skills 目录
```

**命名来源**：
- **RIA** — 赵周《这样读书就够了》的便签拆书法：Reading / Interpretation / Appropriation
- **TV** — Triple Verification，三重验证
- **++** — 面向 agent 执行的扩展：E（Execution 可执行步骤）+ B（Boundary 边界）

---

## 阶段 0：整稿理解（Adler 四步）

### 输入
- 所有选中视频的完整逐字稿
- 博主元信息（昵称、抖音号、粉丝数、作品数）

### 四步执行

#### 第一步：结构（这本书在谈什么？）
- 按主题对视频分组，找出内在逻辑线
- 画出模块关系图（如：执行心法→内容创作→产品设计→商业化）
- 标注每个视频的核心主题和在整体中的位置

#### 第二步：解释（核心论点是什么？）
- 提炼 3-5 个核心论点
- 每个论点必须有原文佐证
- 找出论点之间的逻辑关系（因果、递进、并列）

#### 第三步：批判（作者的盲点和局限）
- 幸存者偏差：作者的成功是否是小概率事件？
- 可复制性：方法论是否假设了作者特有的条件（如表达天赋、已有流量）？
- 适用边界：哪些场景不适用？
- 未讨论的风险：平台规则、合规、竞争等

#### 第四步：应用（这些方法论可以用在什么场景？）
- 直接适用场景
- 需要调整后适用的场景
- 不适用场景

### 产出
`BOOK_OVERVIEW.md`，包含：元信息、结构、核心论点、批判、应用、术语表（初步）、待用户确认问题。

### 用户确认
向用户展示骨架，问："骨架我理解对了吗？有没有你希望重点突出或忽略的方向？"确认后进入阶段 1。

## 阶段 1：5 个提取器并行提取

### 提取器 1：框架提取器
**职责**：识别思维模型 / 决策框架 / 推理方法。

**识别信号**：
- 作者给某个思考方式起了专门的名字
- 某段话在讲"面对 X 类问题时应该..."的通用流程
- 作者反复在不同视频引用同一个思考结构
- 有结构化的 if-then / 先-后 / 从-到 句式

**输出格式**（YAML）：
```yaml
- id: f01
  title: 引流品四要素设计框架
  type: framework
  source_video: 视频1
  source_quote: |
    "引流品的设计难度是很高的，因为它同时起到四个作用..."
  summary: |
    设计引流品时必须同时满足四个约束...
  tags: [product-design, funnel, pricing]
```

### 提取器 2：原则提取器
**职责**：识别原则 / 清单 / 规则 / 格言。

**识别信号**：
- "必须..." / "不要..." / "要记住..." / "三条原则..."
- 编号列表或项目符号
- "每当...就要..." / "只有...才能..."
- 作者在多个场合重复的同一条断言

**常见错误**：
- 把描述当原则："作者告诉我们投资要谨慎"不是原则；"绝不投资你看不懂的生意"是。
- 把一整章当一条：原则必须原子化，一章可能包含 3-5 条独立原则。
- 和 framework 混淆：framework 是"怎么想"，principle 是"做不做"。

### 提取器 3：案例提取器
**职责**：识别作者亲自使用过的具体实例。

**要求**：
- 必须是作者亲自做过的，不是听说的或假设的
- 必须包含：遇到什么问题 → 怎么用方法论 → 得出什么结论 → 实际结果
- 至少 1 条，最多 3 条/方法论

### 提取器 4：反例提取器
**职责**：识别作者警告的失败模式。

**要求**：
- 必须是作者明确说"不要这样做"或"这样做会失败"的
- 必须包含：错误做法 → 为什么错 → 正确做法是什么
- 用于构造 Skill 的 B 段（边界）

### 提取器 5：术语提取器
**职责**：识别关键概念定义。

**要求**：
- 作者给某个概念起了专门名字并给出定义
- 必须包含：术语、定义、为什么重要、相关 Skill
- 最终整理为 `GLOSSARY.md`，是所有 Skill 的共享词典

### 降级方案
当前环境不支持并行 sub-agent 时，用同样 5 个 extractor **串行**执行，产出格式不变。

### 数量预期
- 方法论密集的内容通常有 10-30 个候选框架
- 少于 5 个很可能漏读了
- 多于 50 个可能把"非框架"的东西也算进来了

## 阶段 1.5：三重验证筛选

对每个候选框架/原则执行三重验证，案例/反例/术语不需要验证（它们是辅助材料）。

### V1：跨域佐证
- **标准**：至少 2 个独立视频/段落有佐证
- **为什么**：只在一个地方出现的可能是随口一说，不是核心方法论
- **检查方法**：在所有逐字稿中搜索相关关键词，看是否有多处提及

### V2：预测力
- **标准**：能用它回答一个原文没明说的新问题
- **为什么**：有预测力的方法论才是可迁移的，不是事后诸葛亮
- **检查方法**：假设一个新场景，问"这个方法论能指导我怎么做吗？"

### V3：独特性
- **标准**：不是任何聪明人都会说的常识
- **为什么**：常识不需要做成 Skill，AI 已经知道
- **检查方法**：问"如果我没读过这段内容，我会自然得出这个结论吗？"

### 验证结果处理
- **通过**：写入 `verified.md`，标注通过理由
- **不通过**：写入 `rejected/`，标注淘汰原因（哪一重验证没通过）
- **保留审计轨迹**：rejected/ 目录保留，允许用户事后捞回

### 用户轻确认
筛选完成后，把"通过的 N 个候选标题 + 淘汰的 M 个"列表展示给用户："这 N 个会做成 Skill，有想捞回或砍掉的吗？"得到确认再进入阶段 2。

---

## 阶段 2：RIA++ 构造 Skill

对每个通过验证的单元，按六维度构造 `SKILL.md`。

### R — Reading（原文）
- 直接引用 ≤150 字
- 必须标注出处（视频编号 + 大致位置）
- 若原文是口语化表达，保留原文，不要润色

### I — Interpretation（自述）
- 用**你自己的话**重写方法论的核心骨架
- 5-15 行
- 检查：读完这段，一个没看过原视频的人能否理解这个方法论在做什么？
- 禁止：照搬原文句子 / 堆砌修辞

### A1 — Past Application（书中案例）
- 作者在视频中**亲自**用这个方法论处理过的具体案例
- 至少 1 条，≤3 条
- 每条要点明：遇到什么问题 → 怎么用这个方法论 → 得出什么结论 → 实际结果如何
- 作用：让 Skill 被调用时，AI 有具体的类比素材可用

### A2 — Future Trigger（最关键）
**这决定了 Skill 是否真的会被用起来。**

必须明确：
1. **用户会在什么情境下遇到这类问题？**（场景描述，3-5 条）
2. **这些情境的语言信号是什么？**（用户会说什么样的话）
3. **和哪些相邻 Skill 不同？**（避免和其他 Skill 互相抢调用）

A2 的产出直接写入 Skill frontmatter 的 `description` 字段——AI 据此决定是否激活 Skill。

**好的 A2 示例**：
> 用户在纠结一个决策、列举正面理由却理不出头绪时；或在问"怎么做 X 才能成功"时；不适用于纯信息查询类问题。

**坏的 A2 示例**：
> 用户需要思考时。 ← 太宽泛，会误激活

### E — Execution（可执行步骤）
- 把方法论转成 1-2-3 步骤
- 每一步有**可判断的完成标准**
- 如果有判停点（step 2 之后若 X 则跳到 step 5），显式写出
- 作用：让 AI 在调用这个 Skill 时有明确的执行路径，不是"自由发挥"

**常见错误**：
- "保持客观"不是 step，"列出 3 个最不希望发生的结果"才是。

### B — Boundary（边界）
- 什么时候**不要**使用这个 Skill（反场景）
- 作者在视频里警告过的失败模式
- 来自阶段 0 批判阶段的作者盲点
- 与之相邻但容易混淆的其他方法论
- 作用：**防止乱调用**。没有 B 的 Skill，会在不该用的时候被用，反而帮倒忙。

### Frontmatter 设计
```yaml
---
name: <skill-slug>
description: |
  <A2的浓缩版，≤300字：何时用 + 何时不用 + 关键trigger>
source_book: <博主名>·<主题>
source_chapter: <视频编号>
tags: [tag1, tag2, tag3]
related_skills: []
---
```

## 阶段 3：Zettelkasten 链接

1. 找出 Skill 之间的引用关系（A 依赖 B / A 对比 B / A 组合 B）
2. 在每个 SKILL.md 末尾补"相关 Skills"段，并回填 A2 的"与相邻 Skill 的区分"
3. 生成 `INDEX.md`（含 mermaid 引用图）
4. 把 `candidates/glossary.md` 整理成 `GLOSSARY.md`——它是所有 Skill 的共享词典

---

## 阶段 4：压力测试

对每个 Skill 设计 5-10 条测试 prompt，写入 `test-prompts.json`。

### 必须包含的测试类型
1. **应调用**：明确符合触发条件的场景
2. **不应调用（诱饵）**：看似相关但实际不该调用的场景
3. **边界模糊**：难以判断是否该调用的场景
4. **跨 Skill 混淆**：应触发同组另一个 Skill 的场景（至少 1 条）

### 测试执行
- 优先用独立 sub-agent 盲测每条 prompt
- 由主流程对照预期统计结果
- **未过的回炉重做阶段 2**——不做"表面修补"
- 每个 Skill 的测试结果写入 `<skill-dir>/test-results.md`

---

## 阶段 5：交付

1. 生成 `DIGEST.md`——面向读者的精华长文，满足"不读原文、只看精华"的需求
2. 询问用户是否安装到 skills 目录（安装后可被 AI 直接调用）
3. 用 `present_files` 交付核心产物

### DIGEST.md 结构建议
- 一句话总结
- 五大核心方法论（每个 3-5 句话）
- 十条关键原则
- 常见误区对照表
- 行动清单（按用户类型分组）
- 蒸馏产物说明

## 与 cangjie-skill 的联动方式

### 依赖关系
- douyin-distiller **依赖** cangjie-skill 的方法论
- cangjie-skill 是通用的"蒸馏任何长内容"的元 Skill
- douyin-distiller 把 cangjie-skill 的方法论特化为"蒸馏抖音逐字稿"的具体流程

### 调用方式
1. 用户触发 douyin-distiller 的采集流程（阶段 0-7）
2. 采集完成后，用户说"蒸馏"，进入阶段 8
3. 阶段 8 读取 cangjie-skill 的 `methodology/` 和 `extractors/` 目录，按 RIA-TV++ 流水线执行
4. 蒸馏产物安装到 skills 目录后，可被任何 AI 调用

### 文件引用
- cangjie-skill 的位置：`~/.doubaowork/.../skills/cangjie-skill/`
- 核心方法论：`cangjie-skill/methodology/00-overview.md` 至 `07-stage5-deliver.md`
- 提取器 prompt：`cangjie-skill/extractors/framework-extractor.md` 等 5 个
- 模板：`cangjie-skill/templates/SKILL.md.template` 等

## 常见问题

### Q：蒸馏需要多长时间？
A：取决于视频数量和内容长度。5 条视频（约 2 万字）通常需要 30-60 分钟。阶段 2（RIA++ 构造）最耗时。

### Q：可以只蒸馏不采集吗？
A：可以。如果用户已经有逐字稿文本，可以直接进入阶段 8，跳过采集流程。

### Q：蒸馏出来的 Skill 怎么用？
A：安装到 skills 目录后，AI 会根据用户的问题自动判断是否调用。例如用户问"第一个产品怎么定价"，AI 会自动调用"引流品四要素设计框架"Skill。

### Q：可以只蒸馏部分视频吗？
A：可以。在阶段 4（用户选择作品）时，用户选择哪些视频，就蒸馏哪些。

### Q：蒸馏产物可以修改吗？
A：可以。蒸馏出来的 Skill 是普通的 Markdown 文件，可以随时编辑。也可以喂给 darwin-skill 做自动进化。

## 质量红线（违反则阻止输出）

1. 每个 Skill 必须通过**全部**三重验证
2. 每个 Skill 必须有完整的 R / I / A1 / A2 / E / B 六段
3. 原文引用 ≤150 字
4. 每个 Skill 必须有 `test-prompts.json`，且包含诱饵测试
5. `description` 字段必须明确 trigger 条件，不能只是"一个关于 X 的 skill"
6. 逐字稿必须完整，禁止用占位符
