# 抖音逐字稿采集与内容蒸馏工具

## 这是什么

一个给新手用的一键式工具：你只需要说一个博主的名字或抖音号，它会自动帮你找到博主、拉取所有作品、抓取完整逐字稿、导出成你想要的格式，甚至可以一键把内容蒸馏成可复用的方法论 Skill。

**不需要懂技术，不需要复制链接，不需要知道什么是 API。**

## 使用前提

- **【强制】必须先打开面板**：本 skill 与“逐字稿采集面板.html”硬绑定。收到任何采集/逐字稿/蒸馏相关请求时，第一件事就是检查面板是否已在浏览器中打开。未打开时，必须先引导用户打开面板（文件在本 skill 目录下，文件名“逐字稿采集面板.html”，建议复制到桌面方便双击打开），然后让用户在面板上填好参数，说"按面板执行"后再开始采集。**禁止跳过面板直接采集。**
- **必须在豆包工作中执行**，因为逐字稿获取依赖豆包工作内置的特殊解析能力（普通环境抓不到逐字稿，只能拿到风控空页）。
- 采集博主主页时需要通过内置浏览器登录抖音账号（建议使用小号，仅用于读取公开主页信息）。
- 请仅处理你有权访问和使用的内容，遵守平台规则与法律要求。

## 新手快速开始

**不要直接让用户打字描述需求。** 按以下流程引导：

1. **打开面板**：告诉用户双击“逐字稿采集面板.html”（在本 skill 目录下，或桌面），在浏览器中打开。
2. **填表**：用户按面板上的四步向导填好参数（博主名/抖音号、数量、格式、是否蒸馏）。
3. **说一句话**：用户填完后，在对话框说"按面板执行"（或"填完了"、"读取面板指令"）。
4. **AI 读取面板**：AI 自动读取内置浏览器中面板页面的参数，开始执行。

**面板是唯一的输入入口，禁止让用户手动输入复杂指令。**

## 支持的输入方式

| 输入类型 | 示例 | 说明 |
|---------|------|------|
| 博主昵称 | "七也" | AI 自动在抖音搜索并匹配正确账号 |
| 抖音号 | 主页上“抖音号：”后面那串 | 直接搜索抖音号，不用先找主页 |
| 主页链接 | `https://www.douyin.com/user/xxxxx` | 直接进入主页 |
| 单条视频链接 | `https://www.douyin.com/video/xxxxx` | 只处理这一条 |
| 分享短链 | `https://v.douyin.com/xxxxx/` | 自动解析跳转后的真实链接 |

**不知道链接也没关系，说名字就行。**

## 执行流程（引导式，按顺序执行）

### 阶段 0：启动与确认

**【第一步：面板检测，强制】** 收到用户请求后，首先检查内置浏览器中是否已打开“逐字稿采集面板”（URL 包含 `逐字稿采集面板` 或 `1dy-content-toolkit-panel` 或 `抖音采集蒸馏指令面板`）。

> 本仓库发出去的面板只叫 `逐字稿采集面板.html`。后面两个是**开发期用过的旧文件名**，
> 留在判据里是为了兼容用户桌面上可能还存着的旧副本，不是漏改。

- **面板未打开**：告诉用户"请先打开逐字稿采集面板，填好参数后说'按面板执行'"，并说明面板文件位置（本 skill 目录下的“逐字稿采集面板.html”，建议放桌面）。**停止执行，等待用户打开面板。**
- **面板已打开**：用 `computer_use_tool`（Windows）或 `mac_computer_use_tool`（Mac）读取面板页面上的指令文本（找到"确认并执行"或"生成的指令"之后的内容），解析出参数。
- **用户说"按面板执行"/"填完了"/"读取面板指令"**：直接读取面板参数，跳过以下确认步骤。

**面板参数解析完成后**，确认以下信息（从面板读取，缺失时才主动询问）：

1. **要采集谁？** — 博主名、抖音号或链接。用户只说了名字时，进入阶段 2 自动搜索。
2. **要多少条？** — 默认最新 10 条。用户说"全部"就抓全部，说"最新 N 条"就抓 N 条。
3. **要逐字稿吗？** — 默认要。用户说"只要标题和点赞"就跳过逐字稿。
4. **导出成什么格式？** — 默认 Markdown（每个视频一个文件）。可选：Excel、Word、PDF、Markdown、JSON、飞书多维表格。
5. **需要蒸馏吗？** — 默认不蒸馏。用户说"蒸馏一下"或"提炼方法论"时，进入阶段 8。

**信息确认后再开始执行，不要边做边问。**

### 阶段 1：环境检测

1. 检测操作系统：Mac 用 `mac_computer_use_tool`（plane="bu"），Windows 用 `computer_use_tool`（plane="bu"），代码逻辑一致，均为 `import seed_browser_use as bu`。
2. 如需写入飞书多维表格，检测 lark-cli 身份：运行 `lark-cli api GET /open-apis/authen/v1/user_info --as user`，确认登录的是用户本人账号。沙箱 lark-cli 无权限时尝试系统路径（Mac `/opt/homebrew/bin/lark-cli`，Windows `where lark-cli`）。

### 阶段 2：搜索博主并进入主页

读取 `references/douyin.md` 获取采集细节。

1. **用户提供了博主名或抖音号**：
   - 用内置浏览器打开抖音搜索页：`https://www.douyin.com/search/{关键词}`
   - 检测登录状态：未登录时（页面显示登录弹窗、作品列表显示"服务异常"），调用 `interaction.request_action`（type="browserControl"）请求用户接管完成扫码登录。
   - 登录后，在搜索结果中找到正确的账号（对比昵称、抖音号、粉丝数），点击进入主页。
   - 如果搜索结果有多个相似账号，截图展示给用户确认是哪一个。

2. **用户提供了主页链接或视频链接**：
   - 直接用浏览器打开链接。
   - 分享短链（`v.douyin.com`）先打开获取跳转后的真实 URL。

3. **进入主页后**：等待页面加载完成，确认博主信息（昵称、粉丝数、作品数）正确。

### 阶段 3：拉取作品列表并展示

1. 向下滚动页面，触发懒加载，直到所有作品加载完成（页面底部出现"暂时没有更多了"）。
2. 从 DOM 中提取所有视频信息：
   - 视频链接（`/video/xxxxx` 格式）
   - 标题
   - 点赞数（"万"格式转换为整数，如 3.8万 → 38000）
   - 视频时长
   - 是否置顶
3. 按发布时间排序（最新在前），用户指定数量时只取前 N 条。
4. **结构化展示给用户**：用表格列出编号、标题、点赞、时长、发布日期（如有），让用户一目了然。
5. 询问用户："要处理哪些？说编号就行，比如'要 1、3、5'，或者说'全部'。"

### 阶段 4：用户选择作品

- 用户说编号时，按编号选取。
- 用户说"全部"时，选取所有作品。
- 用户说"点赞最高的 N 条"时，按点赞排序后取前 N 条。
- 确认选择后，进入阶段 5。

### 阶段 5：批量抓取逐字稿

读取 `references/douyin.md` 获取逐字稿提取细节。

1. **默认提取逐字稿**，用户明确说"不要逐字稿"时跳过本阶段。
2. **并行抓取**：一次同时调用多个 `web.fetch`（建议每批 3-5 条），提高效率。
3. 对每条视频链接调用 `web.fetch`：
   - 首次调用 `pagination.offset=0`，检查返回的 `pagination_content` 的 `end_offset` 和 `total_length`。
   - `end_offset < total_length` 时继续分页读取（`offset = 上一次 end_offset`），直到完整。
   - 将所有分页内容拼接为完整文本。
4. **分离逐字稿正文**：第一个空行之前是标题+文案，之后是逐字稿正文。
5. **完整性判断**（满足任一即视为不完整，必须回退）：
   - 逐字稿正文 < 50 字
   - 内容在句子中间中断（末尾不是结束标点）
   - 包含"完整内容"、"web.fetch"、"获取"等占位符文字
   - web.fetch 调用失败或返回空
6. **回退路径**：内容不完整时，加载 `doubao-video-extract` skill，运行 `python3 scripts/minutes/social_video_to_minutes.py "<url>" --run-lark`（下载音频→飞书妙记转写，每条 1-3 分钟）。回退仍失败时，逐字稿字段留空并标注失败原因。
7. **禁止写占位符**：绝不能用"完整内容已通过 web.fetch 获取"这类文字冒充逐字稿。获取失败就留空并说明。

### 阶段 6：AI 扩展字段（可选）

用户需要时（默认不做，用户说"帮我提炼一下"时执行），基于每条视频的标题+介绍+逐字稿，由 AI 生成：

1. **选题方向**：从预设标签中选 1-3 个（如 AI协作方法、认知思维、个人成长、效率工具、自媒体运营等）。
2. **主题总结**：一句话（30-80 字）概括视频核心观点，不重复标题，提炼本质。

**批量生成**：把所有视频的标题+介绍+逐字稿整理为结构化列表，一次性交给 AI 生成，避免逐条调用。短视频（<1500字）用完整逐字稿，长视频（>1500字）可截断至前 2000 字。

### 阶段 7：结果展示与导出

读取 `references/export.md` 获取导出细节。

1. **展示结果摘要**：采集总数、逐字稿成功数、失败数（如有）。
2. **按用户选择的格式导出**：

| 格式 | 说明 | 适用场景 |
|------|------|---------|
| **Markdown**（默认） | 每个视频一个 `.md` 文件，含基本信息+介绍+逐字稿，保存在 `douyin_data/{博主}_{日期}_{数量}条/` 目录 | 通用、可编辑、可直接阅读 |
| **Excel** | 所有视频一个 `.xlsx` 文件，每行一条，列含标题、点赞、评论、转发、日期、链接、逐字稿等 | 数据分析、筛选、排序 |
| **Word** | 每个视频一个 `.docx` 文件，排版美观，含基本信息+逐字稿 | 打印、分享、正式文档 |
| **PDF** | 同 Word，导出为 PDF | 不可编辑的正式交付 |
| **JSON** | 所有视频一个 `.json` 文件，结构化数据 | 程序处理、二次开发 |
| **飞书多维表格** | 直接写入用户指定的飞书表格 | 在线协作、共享 |

3. **导出后验证**：检查文件数量、抽样读取内容、确认逐字稿无占位符、关键字段不为空。
4. **交付**：用 `present_files` 工具把导出的文件交付给用户，说明文件路径、数量、格式。

### 阶段 8：内容蒸馏（可选，与 cangjie-skill 联动）

用户说"蒸馏"、"提炼方法论"、"做成 skill"、"把这些内容拆解成可复用的方法"时执行本阶段。

**前置条件**：
- 已完成阶段 5（有完整逐字稿）
- 已安装 cangjie-skill（`~/.doubaowork/.../skills/cangjie-skill`），未安装时先提示用户安装

**蒸馏输出目录**：在采集输出目录下创建 `distill/` 子目录，结构如下：
```
<博主名>_<日期>_<N>条/
├── 01_xxx.md ... (逐字稿文件)
└── distill/
    ├── BOOK_OVERVIEW.md      (整稿理解)
    ├── verified.md            (三重验证结果)
    ├── INDEX.md               (Skill总览+引用关系图)
    ├── GLOSSARY.md            (术语词典)
    ├── DIGEST.md              (精华长文)
    ├── candidates/            (候选池：框架/原则/案例/反例/术语)
    ├── rejected/              (淘汰的单元+原因)
    └── <skill-slug>/          (每个通过验证的方法论一个目录)
        ├── SKILL.md           (RIA++六段)
        └── test-prompts.json  (压力测试用例)
```

**蒸馏流程**（严格按顺序，每阶段完成后更新进度）：

1. **整稿理解（阶段0）**：读取所有选中视频的逐字稿，执行 Adler 四步（结构/解释/批判/应用），产出 `BOOK_OVERVIEW.md`。向用户确认骨架理解是否正确。

2. **并行提取（阶段1）**：从逐字稿中提取 5 类候选方法论单元，分别写入 `candidates/`：
   - 框架（决策框架、思维模型、推理方法）
   - 原则（规则、清单、准则、格言）
   - 案例（博主亲自使用过的具体实例）
   - 反例（博主警告的失败模式）
   - 术语（关键概念定义）
   - 环境不支持并行 sub-agent 时串行执行，产出格式不变。

3. **三重验证筛选（阶段1.5）**：每个候选框架/原则必须通过：
   - V1 跨域佐证：至少 2 处独立内容支持
   - V2 预测力：能回答一个原文没明说的新问题
   - V3 独特性：不是任何聪明人都会说的常识
   - 通过的写入 `verified.md`，不通过的写入 `rejected/` 并附原因。向用户确认入选名单。

4. **RIA++ 构造 Skill（阶段2）**：对通过验证的单元，按六维度构造 `SKILL.md`：
   - R（原文引用）≤150 字，标注出处（视频编号+时间戳）
   - I（用自己的话重写方法论骨架，5-15行）
   - A1（原文中博主亲自用过的案例，1-3条）
   - A2（未来触发场景：用户什么情况下会需要这个→写入 description）
   - E（1-2-3 可执行步骤，每步有完成标准）
   - B（边界：什么时候不适用、作者盲点、易混淆的相邻方法论）

5. **建立链接（阶段3）**：找出各 Skill 之间的依赖/对比/组合关系，在每个 SKILL.md 末尾补"相关 Skills"，生成 `INDEX.md`（含 mermaid 引用图）和 `GLOSSARY.md`（共享术语词典）。

6. **压力测试（阶段4）**：为每个 Skill 设计 5-10 条测试用例（`test-prompts.json`），至少包括：应调用、不应调用（诱饵）、边界模糊、跨 Skill 混淆（应触发同组另一个 Skill 的场景）。未通过的回炉重做阶段2，不做表面修补。

7. **交付（阶段5）**：
   - 生成 `DIGEST.md` 精华长文（满足"不看原文、只看精华"的需求）
   - 询问用户是否安装到 skills 目录（安装后可被 AI 直接调用）
   - 用 `present_files` 交付核心产物（DIGEST.md + INDEX.md + 各 Skill 的 SKILL.md）

**新手沟通方式**：
- 不要说"RIA++"、"三重验证"、"Adler四步"等术语，说"我先整体理解一下这些内容"、"然后提取里面的方法论"、"再筛选出真正有用的"就行。
- 蒸馏耗时较长（尤其是视频多、内容长时），每阶段完成后告诉用户进度。
- 默认优先构造 3-5 个最核心的 Skill，其余单元作为候选保留，后续可扩展。

**详细方法论**参考 `references/distillation.md`，以及 cangjie-skill 的 `methodology/` 目录和 `extractors/` 目录。

## 关键注意事项

### 新手友好原则
- **用新手能懂的话沟通**，不要说"web.fetch"、"lark-cli"、"API"等术语。说"我正在抓取逐字稿"、"需要你登录一下抖音"就行。
- **每一步都告诉用户在做什么**，不要静默执行很久。
- **默认值要合理**，新手不需要懂参数就能用。

### 抖音采集原则
- **必须通过真实浏览器采集**，禁止用 curl/requests 直接请求抖音 API（会被风控）。
- **登录态是前提**，未登录时作品列表显示"服务异常"，必须请求用户接管登录。
- **不要尝试自动输入手机号/验证码**，抖音有滑块验证，必须用户手动登录。

### 逐字稿完整性（最高优先级）
- **必须获取完整逐字稿**，禁止写任何占位符说明（如"完整内容已通过 web.fetch 获取"）。
- web.fetch 返回被截断时必须分页读取直到完整。
- 获取失败时字段留空并标注原因，绝不能用占位文字冒充。
- 导出后必须验证：逐字稿中不包含"完整内容"、"web.fetch"、"已通过"等占位符文字。

### 数据质量验证
- 写入/导出后必须检查：占位符、逐字稿长度（<50字需排查）、关键字段不为空、点赞/评论/转发为整数。
- 发现问题立即修复，直到验证通过。

### 蒸馏原则
- 蒸馏不是摘要，是把方法论拆成可被 AI 在真实场景下调用的 Skill。
- 每个方法论必须通过三重验证（跨域佐证/预测力/独特性），不通过的淘汰。
- 必须有可执行步骤（E）和边界（B），否则不能叫 Skill。
- A2（触发场景）是最关键的部分，决定了 Skill 是否真的会被用起来。
- 蒸馏产物必须安装到 skills 目录才能被 AI 调用，否则只是文档。
- 详细蒸馏方法参考 `references/distillation.md`。
